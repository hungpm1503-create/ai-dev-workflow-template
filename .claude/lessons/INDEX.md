## How to use

1. When planning a relevant task, read only this index and matching records.
2. Prefer `ADOPTED` guidance. `PROPOSED` and `VALIDATED` are not permanent behavioral rules.
3. A record should point to a reproducible result and immutable Git/CI/PR references wherever available.
4. Capture drafts under ignored `.claude/experience-drafts/` and follow `.claude/lessons/EXPERIENCE_TEMPLATE.md` after review.
5. Retire or consolidate outdated records; do not append every task failure.

The template deliberately uses Markdown and Git references, not a separate vector DB or a duplicated snapshot of all harness files.
