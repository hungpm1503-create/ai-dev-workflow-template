# Controlled microbenchmark: Working Memory versus full replay

This is a small, reproducible **offline** comparison on one toy implementation task:
> Normalize a coupon code by trimming and uppercasing; reject whitespace-only codes and non-string input.

## Reproduce

```bash
bash scripts/benchmark-workflow-resume.sh
```

This task has four acceptance assertions. The script creates a broken Node.js fixture, confirms that the test fails, applies a deterministic corrected implementation, and confirms 4/4 checks pass. **The implementation is scripted, not generated by Claude or Codex.**

For the *same completed task*, the comparison measures:

1. **Full replay baseline:** read the task handoff, a deliberately verbose 150-line synthetic trace, and final completion note.
2. **Working Memory v0.4:** read only local `STATE.md` plus `LATEST.md`, with a separate per-run metadata checkpoint. All files are temporary and ignored by Git.

It checks that the compressed path still contains the task objective, test result, remaining review state and concrete next action. It outputs exact UTF-8 byte counts, word counts and percent byte reduction for that **particular artificial workload**.

## What this does *not* establish

- No independent Claude/Codex model invocation; no observed difference in AI reasoning quality or bugs.
- No actual input/output model token counts, billable cost or wall-clock agent completion time.
- The baseline is **intentionally verbose** and is not an optimized v0.3 agent. The percentage is a packing comparison, not a guaranteed savings rate.
- The next session still needs to verify current code/CI state; memory is untrusted context.
- Local working memory cannot automatically synchronize between separate clones or remote machines.

## Proper A/B benchmark with real agents (future manual pilot)

Run one **identical** task independently with an unchanged baseline harness and v0.4, on two reset worktrees using the same model/version, sandbox, tools, constraints and acceptance tests. Repeat enough independent trials to reduce sampling noise. Record actual model usage, test pass rate, rework count, repeated file reads, wall time and reviewer findings. Do **not** use one model's result to seed the other. Compare only after independently confirming both code changes and review outcomes.

The offline benchmark is a smoke test of the **memory/resume mechanism**, not evidence that ECC-inspired additions improve real-world coding productivity.
